# Decisions

Standing decisions are in docs/factory/BATCH1_PLAN.md (Mongo instead of Postgres, Better Auth, Stripe first, Mailer interface, Vercel-first, keep 3 deployments).

## Phase 0 (5 Nov 2026)
1. **Cloudflare Workers/D1/KV → Vercel + Mongo + R2.** Hot path = Vercel Edge route reading a pointer JSON from R2 (behind `PointerStore`). Reason: owner's Vercel-first rule; keeps "never touches the DB" true.
2. **Paddle → Stripe** via `BillingAdapter`, per BATCH1_PLAN. Plans/prices exactly per the brief; `metadata.app=hotrail`, lookup keys `hotrail_*`.
3. **Bundle host:** `hotrail-cdn.buffersoltech.com` (first level, Universal SSL, R2 custom domain) instead of `/f/*` through Vercel, to avoid Vercel bandwidth cost. `/f/<sha256>` redirects there. Single hostname rule is about avoiding deeper subdomains; this is not deeper.
4. **Cron:** Cloudflare Worker per minute + Vercel daily backstop (Hobby limits).
5. **API key hashing:** 256 bit random keys + SHA 256 with prefix lookup instead of argon2id (high entropy secret; fast verify on the CLI path). Deviation from the brief, same practice as GitHub/Stripe.
6. **Signing:** customer held Ed25519 keys sign manifests in the CLI (server never holds a private key by default); managed signing is opt in.
7. **Spam/abuse:** kit ALTCHA instead of Turnstile. **Email:** Resend adapter now, Postfix later (workbook's banned list lifted by owner decisions). **Backups:** GitHub Actions mongodump to R2.
8. **Design overrides (written per DESIGN_PLAYBOOK §3):** three font families (Barlow Condensed, Atkinson Hyperlegible, Red Hat Mono, all OFL, via next/font so self hosted) instead of the skill's one-typeface whitelist; workbook dark palette instead of the six skill dark values; Phosphor icons (skill whitelist) in place of the workbook's Lucide; no hero text gradient. Reason: ICP is a developer under incident pressure, the workbook specifies the signal box system, and none of the category uses it.
9. **Plugin e2e** runs in GitHub Actions (macOS runner + Android emulator) because there is no Mac farm.
10. **Oddities resolved:** Free plan has 2 apps, paid unlimited; "annual = 2 months free" is NOT used in copy (real saving is about 14%, state the dollar figure instead); no GBP/CAD prices until Stripe currency options are configured; no testimonials or logos until real ones exist.
11. **Palette revised (5 Nov, orchestrator review):** primary family changed from railway green to deep signal navy with amber as the highlight, to avoid looking like DockCrate (dock green on warm paper) in the public side by side. Green remains only as the go lamp. Tokens in DESIGN.md section 5; mock and screenshots regenerated.

- 2026-11-05 (M2): **Bundle ids are unique across the product, not only per org.** Devices send only `app_id`, so the hot path needs one global lookup. A second org that tries an existing id gets 409 `app_id_taken`. Pointers live at `ptr/<bundleId>/...`; stored objects are keyed by the app's internal id (`blobs/<appDocId>/<sha>`, `zips/<appDocId>/<bundleDocId>.zip`), so a version can never overwrite another's bytes.
- M2: **Two upload paths, one pipeline.** `POST /api/v1/bundles` (zip body, server signs with a per-app managed key sealed by AES-256-GCM under `SECRETS_KEK`, AAD = app id) and the CLI's `upload/plan` + `upload/finalize` (customer key signs; first signed upload registers the public key, the CLI now sends `publicKey`; once a key is registered, unsigned uploads are refused). An app is "managed" or "customer" by whichever path created it; the other path gets 409 `customer_signed_app`. Finalize re-reads every blob, re-hashes it and runs the magic byte check again, because presigned R2 PUTs bypass our server. The CLI path builds the zip server side (the stock Capgo plugin needs a zip and its sha256 as `checksum`); capped at 150 MB per function invocation.
- M2: **Hot path = `src/lib/hotpath/check.ts`**, imports only core and a `PointerReader`. It runs on Node today (`/api/v1/updates/check`), and moving to Edge is the one-line `runtime` switch once the reader is R2's public host. It never reads the DB: last-seen devices are recorded by the stats beacon route only. Routes live under `/api/v1/updates/{check,stats,channel}` as specified; the `/api/updates` aliases in ARCHITECTURE.md are not added (the plugin only needs its three URLs changed).
- M2: **Pointers are rewritten by one function (`publishPointers`)** after every release, rollback, pause, resume, auto-pause and override change; the index is written last. A device override ignores the target channel's rollout percent but not its pause flag. Overrides in the index are capped at 500 (ARCHITECTURE section 2); beyond that `override_limit`.
- M2: **Channel concurrency** is optimistic (`rev` compare-and-set, 409 `channel_busy`) instead of the Mongo lease from the architecture doc; same guarantee for the console and CLI, simpler. Rollback sets previous to null (a second reverse is refused) so a bad bundle can never become the "previous" again. A release always lifts a pause.
- M2: **Auto-pause** evaluates one channel after every failure beacon (failed + rolled back over applied + failed, last two 5 minute buckets, at least `minSample` outcomes, strictly above the threshold). The per-minute Worker sweep over all channels stays in M3. Success events are stored at 100% in M2 (the 10% sampling in the architecture would distort the failure rate; rollups come with usage buckets in M3).
- M2: **API key scope** lives in Better Auth key `metadata.scope` (`all` default, `upload`, `read`; anything unknown means `read`). Console requests map role to scope (`data:write` = all, else read). Free plan app cap (2) is enforced when an app is created.
- M2: **Storage selection**: `BUNDLE_STORE=memory|fs|r2`; default is r2 only when all four R2 variables are present, else memory. SigV4 is our own WebCrypto code, checked against the AWS `get-vanilla` vector. Memory/fs stores serve downloads from `/api/v1/files/<key>` (only `zips/` and `manifests/`); R2 uses `R2_PUBLIC_BASE` (the CDN host).
- M2: Playwright is configured to honor `PW_CHROMIUM` (path to a system Chromium) because the sandbox has no downloaded browser.

- 2026-11-05 (M3): **Native compatibility is an allow list once builds are recorded.** An app with no recorded store builds behaves as before (explicit `allowedNativeBuilds` or any build). After the first `native register`, `publishPointers` writes `allowedNativeBuilds` = builds whose fingerprint equals the bundle's, or that carry every plugin the bundle needs on the same Capacitor and plugin majors (a superset is fine), plus the bundle's explicit list, and sets `enforceNativeBuilds` (new optional field on `ChannelPointer`; an empty enforced list refuses everyone). A store build the server has never seen gets no update: it cannot be verified, and recording it republishes pointers. The hot path still never reads the DB. Bundles carry optional `nativeInfo` (CLI sends it on plan; zip upload takes `?native=<json>`); without it only fingerprint equality or the allow list applies.
- M3: **Usage buckets** are incremented in `ingestStats` once per stored event, so they equal the raw events by construction (success events are still stored at 100%, so there is no sampling error). Buckets keep 30 days (`BUCKET_TTL_DAYS`), raw events 7. The adoption chart plots cumulative applied per bundle version from the buckets, not live device counts.
- M3: **Auto-pause sweep** loops over all live, unpaused channels and calls the same `evaluateAutopause` the beacons use (idempotent, compare-and-set). One failing channel is counted in `errors` and never stops the sweep. Worker default jobs are `autopause-sweep,webhook-retries`; Vercel Cron runs the sweep once a day as a backstop.
- M3: **Delete guard** refuses a bundle that is live on any channel (`bundle_live`) and also a bundle that is a channel's reverse target (`bundle_rollback_target`), because deleting it would break one click rollback. Deletion is soft; blobs stay until a cleanup job exists.
- M3: **MCP**: stdio package only (official `@modelcontextprotocol/sdk`); release/rollback without `confirm: true` return a dry run and never call a mutating endpoint. The HTTP `/api/mcp` endpoint from ARCHITECTURE.md is deferred.
- M3: **Plugin**: logic lives in a pure TypeScript core over an injected native bridge so state machine, retries and verification are unit tested; native Swift/Kotlin only do file IO, hashing, unzip (zip-slip safe) and `setServerBasePath`, and also keep a native crash guard (revert on the second launch with an unconfirmed trial). Signed-only mode when `publicKey` is set. All native files are written but not compiled in this environment; `plugin-ci.yml` is the first real build.
- M3: **Device lookup** needs the app's own id, so beacons now store `custom_id` on the device record (hot path unchanged: still no DB reads).

- 2026-11-06 (M4): **MAU is counted off the response path.** `/api/v1/updates/check` answers from pointers as before and then (`after()`) records the device in `active_devices` (unique per org, app, month, device). The first sight in a calendar month (UTC) increments the `mau` usage counter. A per instance Set avoids a DB round trip for devices already seen. The hot path itself still never reads the database.
- M4: **Limit behaviour.** At 100% of the plan's MAU (plus the owner's overage allowance on paid plans) pointers are republished with `limited: true`, so `decideUpdate` offers nothing: new downloads pause for everyone, installed apps keep their bundle. State is stored per org (`org_flags` key `limited`); it is re-evaluated on every new MAU, on the Stripe webhook (`syncOrgLimits`, so plan changes apply within seconds, well inside the one minute target) and by the `limits-sweep` cron (month rollover, plan expiry).
- M4: **Emails.** Usage emails (50/70/90/100% of included MAU) go to org owners (admins if no owner), once per threshold per period (`org_flags` `usage-notice:<period>:mau:<pct>` written with ifAbsent), one email for the highest threshold crossed. They are transactional (no unsubscribe). Release, rollback and auto-pause emails go to every member and are category `notification` with scope `notify:<kind>`; preferences are suppression entries, so the one-click `List-Unsubscribe` link and the settings page share one mechanism. Mail failures never fail a release (Notifier swallows and logs).
- M4: **Overage is reported, not billed.** Brief: $0.0015 per extra MAU, billed only with confirmation, caps set by the customer. We store the owner's cap (whole USD per month, paid plans only), allow `included + cap/0.0015` MAU before pausing, and show used, over, and dollars on `/app/billing`. No Stripe metered price exists yet, so nothing is charged. The "3 months running suggests upgrade" nudge is not built.
- M4: **Storage is fair use, enforced softly:** new uploads are refused (402 `storage_limit`) when stored bundle bytes (sum of bundle sizes, which overcounts shared blobs) would pass the plan's GiB. Existing bundles keep serving. **Event retention** uses the plan's `event_days` when an event is stored. Build minutes are v1 (shown, not metered). Auto-pause is not gated by plan in code (pricing lists it under Maker).
- M4: **Delta delivery.** Pointers carry `manifestUrl` and `filesUrl` (`publicUrl("blobs/<appDocId>")`, the plugin appends `/<sha256>`); `decideUpdate` adds `manifest_url` and `files_url` only when both are present. `blobs/` joined the public prefixes (content addressed, readable only by hash). Stock Capgo clients ignore the extra keys; the contract fixture lists them as optional.
- M4: **Failure spike event** is `channel.failure_spike` (not a separate "release.paused"): sent once per 30 minutes per channel when the failure rate reaches half the auto-pause threshold with at least `minSample` outcomes. Pause is `channel.paused` (cause `manual` or `autopause: ...`), release `release.created`, rollback `release.rolled_back`.
- M4: **Audit.** Key and member changes are audited from one Better Auth `hooks.after` (mapping in `src/lib/auth/audit-hook.ts`), releases and rollbacks were already audited. `/api/audit/export` streams CSV (newest first, max 10,000 rows, `from`/`to`), with spreadsheet formula neutralisation. Found and fixed: the audit page called a client-only `formatDate` from a server component and crashed as soon as the log had rows.
- M4: **Encrypted bundles, TS half only.** `session_key = <iv b64>:<RSA-OAEP-SHA256 wrapped AES key b64>`; the plugin unwraps with WebCrypto using a configured `privateKey`, asks the bridge to `decryptFile` (native, not written), checks `checksum` on the decrypted zip, and with a `publicKey` verifies each extracted file against the signed manifest. No delta for encrypted bundles. Server and CLI do not produce encrypted bundles. This is our own scheme (the Capgo plugin's is not copied).
- M4: **Bundle delete frees storage:** zip, manifest and blobs not listed in any remaining bundle's manifest are deleted (best effort; failure is recorded as `filesDeleted: -1` in the audit entry).
- M4: **Not done:** HTTP `/api/mcp` endpoint (needs the SDK's Streamable HTTP transport plus per request key auth; not small enough to ship without a network to try it), release dialog, status page, abuse rules, backups drill, Postfix. `package-lock.json`: `npm install --package-lock-only` ran against the registry and changed nothing, so the lock is already consistent. No new dependencies were added.

- 2026-11-07 (M5 review): **Findings live in `docs/REVIEW.md`.** All 9 P0s are fixed with tests; the open P1s and P2s are listed there with fixes.
- M5: **Devices only ever download a zip the server wrote.** The zip upload path stores `writeZip(inspected entries)`, never the customer's bytes. The CLI path already did this. Zip checksums therefore differ from the uploaded file. That is intended, and the manifest is still over the same file contents.
- M5: **A Capacitor app id is never handed to a second org.**
  - Account deletion retires the app's pointers first. A tombstone index means devices get no update, and the channel pointers are deleted.
  - `ensureApp` refuses any app id whose pointer index already exists in the store (409 `app_id_taken`, "contact support"). The pointer namespace is the thing that controls installed devices, so it is the reservation record. No DB change was needed.
  - Releasing an id is a manual support action: delete `ptr/<appId>/index.json` after checking the old owner's consent.
- M5: **Pointer publishing re-checks after writing.** `publishPointers` writes, recomputes and writes again if the state changed (max 5 passes, else it throws `pointer_publish_unstable`). This avoids a lock service. It costs one extra round of reads per publish.
- M5: **Plugin resets on a new store build.** It keeps `nativeBuild` in its state. When `versionBuild` changes, every downloaded bundle is dropped and the built-in assets load (one reload). The beacon `reset_native_change` is "other" for metering, and the version is not blacklisted. Native Swift/Kotlin should get the same check before load (REVIEW P1-12).
- M5: **Production refuses a volatile bundle store next to a real DB** (`storeFromEnv` throws). The all-memory demo and an explicit `BUNDLE_STORE=memory` stay allowed. The equivalent DB guard is deferred because `next build` runs as production without a DB (REVIEW P1-18).
- M5: **Copy changes without asking the owner:**
  - SSO is labelled "coming in v1".
  - The unconfirmed "3 months free for Appflow teams" offer is removed.
  - The Capacitor answer now states the plugin's real peer range (6 or later).
  - Overage is described as reported, not charged.
  - The 10% sampling claim is removed.
  - The legal placeholders stay owner items (MANUAL_STEPS 9).
- M5: **API key roles.** Owner and admin get `apiKey:create/update/delete` because Better Auth's api-key plugin checks those actions. Members only read, and viewers have no access.
- M5: **`/api/health`** does one indexed read with a 2 s timeout and returns 503 when the DB fails. The update check stays independent of the DB.
- M5: **Indexes on first connection.** Memoized per instance on globalThis, not awaited by requests (health stays fast), never at build or import, index conflict codes 85/86 are logged and skipped, other errors are warned and retried on the next cold start.
